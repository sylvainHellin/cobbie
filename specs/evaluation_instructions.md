# Evaluation Instructions for BIM Question Answering Systems

## 1. Introduction

### System Overview
This document provides evaluation instructions for assessing the quality of answers generated by BIM (Building Information Modeling) question answering systems. These systems are designed to answer questions about building data encoded in IFC (Industry Foundation Classes) files by processing natural language queries and extracting information from BIM models.

### Purpose of Human Evaluation
This evaluation validates automated LLM-as-a-judge evaluation by comparing it against human expert judgment. You will assess system-generated answers using the same five-criteria framework that the automated evaluator uses, enabling calculation of inter-rater reliability (Krippendorff's alpha) and identification of systematic differences between human and automated evaluation.

### Your Role
As a human judge, you will independently evaluate a set of question-answer pairs using the provided Excel grading sheet. Your ratings will be compared with those of the automated judge and other human judges to measure agreement and validate the automated evaluation approach.

## 2. Evaluation Framework

### Overview
Each answer is evaluated using **five independent criteria**. These criteria must be assessed separately without allowing one judgment to influence another. The final binary classification (correct/wrong/abstained) is automatically derived from your criterion ratings.

### The Five Criteria

#### 2.1 Abstention (Boolean: TRUE/FALSE)

**Definition:** Did the system explicitly decline to answer the question?

- **TRUE** if the response contains explicit refusal language:
  - "I cannot determine..."
  - "Insufficient information to answer..."
  - "This data is not available and I cannot provide an answer..."
  - "I am unable to answer this question..."

- **FALSE** if the system provided an answer, even if expressing uncertainty or providing conditional statements

**Critical Rule:** If Abstention = TRUE, all other criteria (Faithfulness, Completeness, Transparency, Relevance) must be set to 'Na' and evaluation stops.

#### 2.2 Faithfulness (Yes/No/Na)

**Definition:** Are all claims in the answer grounded in valid sources appropriate for the question category?

**Category-Specific Grounding Rules:**

| Category | Valid Sources | Invalid Sources |
|----------|--------------|-----------------|
| Category 1 | BIM element properties only | Any computations or derivations |
| Category 2 | BIM data + simple computations (count, sum, average) | Complex geometric calculations |
| Category 3 | BIM geometry + complex computations | Unstated assumptions |
| Category 4 | BIM data + computations + **explicitly stated assumptions** | Implied or unstated assumptions |

**Numerical Tolerance:**
- Continuous measurements (lengths, areas, volumes): Within 2% of ground truth is acceptable
  - Formula: `|system_value - ground_truth| / ground_truth ≤ 0.02`
- Discrete counts (number of elements, rooms, floors): Exact match required

**Rating:**
- **Yes:** All claims are properly grounded according to category rules
- **No:** Contains hallucinations, computational errors, or violates category rules (e.g., unstated assumptions in Category 4)
- **Na:** Only if Abstention = TRUE

#### 2.3 Completeness (Yes/No/Na)

**Definition:** Are all relevant facts included to fully answer the question?

**Rating:**
- **Yes:** All relevant facts are present for enumerable questions; reasonable detail level for open-ended questions
- **No:** Missing critical facts, providing only a subset of requested items, or partial answer to multi-part question
- **Na:** If Abstention = TRUE **or** if the question is open-ended with no objective completeness standard

**Example:** If the question asks "Which rooms are adjacent to room A101?" and the answer lists only 2 of 4 adjacent rooms, this is incomplete.

#### 2.4 Transparency (Yes/No/Na)

**Definition:** Are sources and methods explicitly disclosed for each claim in the answer?

**Requirement:** Every claim must cite the specific property, computational method, or assumption used.

**Transparent Examples:**
- "Width is 900mm from property Door.Width"
- "24 windows counted from IfcWindow elements"
- "Area is 245.8 m² calculated using ISO 9836"
- "Assuming typical commercial HVAC systems (20-25 year lifespan)..."

**Non-Transparent Examples:**
- "Width is 900mm" (no source cited)
- "According to the model..." (too vague)
- "Generally..." or "Typically..." (hedging without explicit assumption statement)

**Rating:**
- **Yes:** All claims have explicit source/method disclosure
- **No:** Missing disclosure for any claim
- **Na:** Only if Abstention = TRUE

#### 2.5 Relevance (Yes/No/Na)

**Definition:** Does the answer directly address the question asked?

**Rating:**
- **Yes:** Addresses the correct aspect/property and scope; may include additional relevant information
- **No:** Answers wrong property, wrong scope, or misunderstands question intent
- **Na:** Only if Abstention = TRUE

**Example:** If asked about door width but answer provides door material and fire rating, this is irrelevant.

## 3. Question Categories

Each question belongs to one of four categories. The category determines which sources are considered valid when evaluating Faithfulness.

| Category | Name | Description | Faithfulness Rule |
|----------|------|-------------|-------------------|
| **1** | Direct Property | Direct information retrieval from BIM element properties | BIM properties only, no computations permitted |
| **2** | Aggregation | Simple unambiguous computations | Counting, summing, averaging are valid; must be deterministic |
| **3** | Computation | Complex geometric or spatial calculations | May derive values not explicitly stored; multiple calculation approaches acceptable |
| **4** | Estimation/Unavailable | Required information not in model | Assumptions are acceptable **only if explicitly stated verbatim** |

## 4. Evaluation Procedure

The evaluation process consists of eight steps for each question:

1. Review the question, the system's answer, and the ground truth reference answer
2. Note the question category, which is displayed in the grading sheet
3. Assess whether the system abstained from answering:
   - If the system explicitly declined to answer → mark Abstention as TRUE, set all other criteria to 'Na', and proceed to the next question
   - If the system provided an answer → mark Abstention as FALSE and continue with the remaining criteria
4. Assess Faithfulness by applying the category-specific grounding rules and numerical tolerance thresholds
5. Assess Completeness by identifying any missing relevant facts
6. Assess Transparency by verifying that all claims include explicit source or method citations
7. Assess Relevance by confirming the answer addresses the question as asked
8. Optionally, provide justification in cases where you assign 'No' ratings or make borderline decisions

## 5. Key Guidelines

### Criterion Independence
Evaluate each criterion separately. Do not let one judgment influence another. All combinations are valid:
- An answer can be faithful but incomplete
- An answer can be complete but unfaithful
- An answer can be transparent but irrelevant

### Using 'Na' Appropriately
Use 'Na' only for structural reasons:
- Abstention = TRUE (mandatory for all criteria)
- Completeness for open-ended questions with no objective standard

Do **not** use 'Na' for:
- Uncertainty about how to rate
- Difficulty judging
- Borderline cases (choose Yes or No based on best judgment)

### Justification Field
Provide brief justification (2-3 sentences) when:
- Assigning any 'No' rating
- Making borderline decisions
- Deviating from what might be expected

### Numerical Tolerance Application
For continuous numerical values, apply the 2% tolerance rule:

**Example:** Ground truth = 500 m²
- Acceptable: 490 m² to 510 m² (within 2%)
- Unacceptable: 520 m² (4% deviation, exceeds tolerance)

For discrete counts, exact match is required:
- Ground truth: 24 windows
- Acceptable: 24
- Unacceptable: 23 or 25

---

These guidelines establish a systematic framework for evaluating BIM question answering systems. Consistent application of these criteria across all evaluators enables reliable measurement of inter-rater agreement and validation of automated evaluation methods. When uncertain about edge cases, document your reasoning in the justification field to facilitate subsequent analysis of disagreement patterns.
