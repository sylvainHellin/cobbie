# BIM Question Answering Evaluation Instructions

## Overview

This document provides instructions for evaluating answers generated by BIM Question Answering systems. The evaluation assumes that questions have already been classified into one of four categories based on data retrieval complexity. Each answer is assessed using five binary criteria, with results recorded as Yes, No, or N/A (not applicable).

The evaluation follows a systematic workflow: first determine whether the system attempted to answer or abstained, then if an answer was provided, evaluate four quality dimensions: faithfulness, completeness, transparency, and relevance.

## Backgound Information: Question Categories

Questions are classified into four categories that reflect the complexity of data retrieval and computation required to answer them. The question category will be provided to you along with the question and answer. The category of the question influences how some criteria need to be evaluated (particularly the faithfulness criterion).

Category 1 represents direct information retrieval, where answers draw on explicitly stored BIM element properties without requiring any computation. Questions in this category ask for property values that exist directly in the model, such as dimensions, materials, or identifiers. A question asking for the width of a specific door exemplifies Category 1.

Category 2 involves computational aggregation, where answering requires simple, unambiguous mathematical operations on directly accessible data. The individual data points exist explicitly in the model, but the answer requires counting, summing, averaging, or filtering. Questions asking how many windows exist in a building or what the total length of all walls is fall into this category. The computations are deterministic with only one correct approach.

Category 3 encompasses geometric and spatial computation, where answers must be derived from geometric or topological relationships not explicitly stored in the model. Calculating gross floor area according to a specific standard, determining volumes from spatial data, or computing distances between elements exemplifies this category. These questions are distinguished by the need for geometric analysis and the potential for multiple valid calculation approaches, such as different area measurement standards.

Category 4 addresses incomplete information scenarios, where required information is not available in the BIM model. Questions about environmental impact data, expected equipment lifespans, construction costs, or regulatory compliance typically fall into this category. These questions test whether systems appropriately handle uncertainty through explicit assumption disclosure or appropriate abstention. For Category 4, explicitly stated assumptions become valid grounding sources because the disclosure itself enables users to evaluate assumption validity.

## Evaluation Workflow

Begin by assessing whether the system provided an answer. If the system explicitly abstained or declined to answer, mark all quality criteria as not applicable and stop. Abstention is not a failure but rather an appropriate response when required information is unavailable or the system recognizes it cannot provide a reliable answer.

If an answer was provided, proceed to evaluate the four quality criteria independently. Each criterion addresses a distinct aspect of answer quality and should be assessed separately without allowing one judgment to influence another.

## Criterion 0: Answer Attempted

Determine whether the system generated an answer or explicitly abstained. Record Yes if any answer content was provided, even if partial or hedged with uncertainty. Record No only when the system clearly declined to answer, such as stating that required information is not available in the model or that it cannot answer the question.

If the system abstained, mark all subsequent criteria as N/A and complete the evaluation. If an answer was provided, proceed to evaluate Criteria 1 through 4.

## Criterion 1: Faithfulness

Faithfulness evaluates whether all claims in the answer are grounded in acceptable data sources for the question's category. The acceptable grounding sources vary by category: Category 1 questions require strict grounding in BIM model data only, Category 2 permits simple unambiguous computations on BIM data, Category 3 allows complex geometric computations derived from BIM data, and Category 4 accepts explicitly stated assumptions in addition to BIM data and computations.

An answer passes faithfulness when every claim can be traced to acceptable sources for its category. For Categories 1 and 2, this means all values must come from BIM properties or correct computations on those properties. For Category 3, claims may be based on geometric derivations from BIM geometry, even when those derived values are not stored as explicit properties. For Category 4, assumptions become valid grounding sources only when explicitly stated in the answer.

Numerical accuracy is evaluated with reasonable tolerance. For continuous measurements such as lengths, areas, and volumes, values within 2% of the correct value are considered acceptable, accounting for rounding and unit conversion. For discrete counts, exact matches are required.

An answer fails faithfulness when it contains hallucinated information not grounded in acceptable sources, incorrectly represents BIM data, contains computational errors, or makes unstated assumptions. For Category 4 questions specifically, making assumptions without explicitly stating them constitutes a faithfulness failure, even if the assumptions themselves might be reasonable.

Consider a Category 1 question asking for a door width. If the answer states 900mm and the BIM property shows 900mm, faithfulness passes. If the answer states 1000mm when the property shows 900mm, it fails. For a Category 4 question about HVAC lifespan where no data exists in the model, an answer stating "Based on typical HVAC systems, the expected lifespan is 20-25 years" fails because the assumption is implied rather than explicitly stated. An answer stating "The lifespan data is not available in the model. Assuming typical commercial HVAC systems, the expected lifespan is 20-25 years" passes because the assumption is explicitly disclosed.

## Criterion 2: Completeness

Completeness assesses whether the answer includes all relevant facts necessary to fully address the question. An answer passes when it provides all requested information without omitting critical elements. It fails when missing facts that are necessary to fully answer the question.

For questions requesting enumerations or lists, completeness requires that all elements be present. If asked which rooms are adjacent to a specific room and four rooms are actually adjacent, an answer listing only one or two of them is incomplete even if the listed rooms are correct. For questions requesting specific measurements or properties from multiple elements, all requested values should be provided.

Mark completeness as not applicable when the question is open-ended and no objective standard for completeness exists. Questions beginning with "describe" or "explain" often fall into this category, as multiple levels of detail could reasonably be considered complete.

Completeness is evaluated independently from faithfulness. An answer can be faithful but incomplete, providing correct information about only some of the relevant elements. Conversely, an answer could be complete in scope but unfaithful if it includes all relevant elements but gets some facts wrong.

## Criterion 3: Transparency

Transparency evaluates whether the answer explicitly identifies the source or method for each claim made. An answer passes when every claim is accompanied by disclosure of where the information came from or how it was derived.

For claims based on BIM data, transparency requires identifying the specific property accessed. For computations, the method employed should be stated. For assumptions, the assumption itself must be explicitly declared. The key requirement is that source or method disclosure must be explicit and clear, not merely implied or suggested through hedging language.

An answer stating "The door width is 900mm from property Door.Width" demonstrates transparency by citing the specific property. Simply stating "The door width is 900mm" fails to disclose the source. Vague references such as "according to the model" are insufficient because they do not specify which property or element was accessed.

For computational questions, stating the method is essential. An answer to "How many windows are there?" that states "There are 24 windows counted from model elements" passes transparency. Simply stating "There are 24 windows" provides no methodological disclosure. For geometric computations where multiple valid approaches exist, method disclosure is particularly critical. An answer stating "The gross floor area is 245.8 m² calculated using ISO 9836 standard" enables users to understand which calculation approach was employed and verify whether it aligns with their requirements.

Hedging language does not constitute explicit disclosure. Phrases such as "typically," "generally," "based on common practice," or "usually" suggest assumptions without explicitly stating them. These fail the transparency criterion. Explicit disclosure requires direct statements such as "using method X," "from property Y," or "assuming Z."

## Criterion 4: Relevance

Relevance assesses whether the answer directly addresses the question asked. An answer passes when it responds to what was actually asked, addressing the correct aspect or dimension. It fails when off-topic, when it misunderstands the question, or when it addresses a related but different aspect than what was requested.

If asked "What is the door width?" an answer providing the width is relevant. An answer providing the door material instead fails relevance by addressing the wrong property. If asked "How many windows are on the south facade?" an answer providing the total window count for the entire building fails by addressing the wrong scope.

For questions with multiple parts, relevance does not require that the answer address all parts. If a question asks both for a count and for specific identifying information, providing only the count still satisfies relevance (but would fail completeness).

Relevance focuses on whether the question was addressed, not whether additional information was provided. An answer that addresses the question but also includes tangential information still passes relevance. The criterion fails only when the answer does not address what was actually asked.

## Recording Results

For each evaluated question-answer pair, record the answer attempted status, and the assessment for each quality criterion. Use Yes when the criterion is satisfied, No when it fails, and N/A when the criterion does not apply.

Include brief notes when assessments might not be obvious, particularly for faithfulness judgments where you had to verify claims against BIM data, or for completeness and transparency where boundary cases required judgment.
